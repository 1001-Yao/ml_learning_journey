
### 一、困惑度评估


分布内（In-Distribution, ID）：训练集和测试集来自同一个数据集（i.i.d. 独立同分布）。比如，用维基百科的训练集训，用维基百科的测试集考。

分布外（Out-of-Distribution, OOD）：测试集的数据分布、任务类型、甚至语言，跟训练集完全不同。目前主流且‘唯一’有效的标准

### 二、考试类基准

#### 1、MMLU(大规模多任务语言理解)
- 包含 57 个科目（例如：数学、美国历史、法律、道德），均为多项选择题。
    
- “由研究生和本科生从网上免费可用的资源中收集而来”。
    
- 尽管名字叫“语言理解”，**MMLU 实际上是测试（模型掌握的）知识，而不是语言理解能力**
    
- 在 GPT-3 上使用少样本提示（few-shot prompting）进行评估。

#### 2、MMLU-pro
- 数据规模与领域：包含 超过12,000道 题目，覆盖生物、商业、化学、计算机科学等 14个 领域。-1

- 关键升级：从4个选项增加到10个。这将随机猜测的准确率基准从 25% 大幅压低至 10%，迫使模型必须具备真才实学才能得分。-3

- 难度提升效果：相比 MMLU，模型在 MMLU-Pro 上的准确率普遍下降了16%到33%，有效拉开了不同能力模型的区分度。

- 评估范式转变：在 MMLU 上，直接回答往往效果不错；但在 MMLU-Pro 上，思维链（CoT）推理能带来显著的性能提升，表明其包含了更多需要复杂推理的题目。

- 稳定性：对提示词变化的敏感度从 MMLU 的 4-5% 降低到 2%，评估结果更稳健。
#### 3、GPQA
标志着评估重心从“广博知识”向 “专家级深度推理” 的关键转折。其核心是 “Google-Proof”（谷歌搜不到），确保题目无法通过简单的网络搜索找到答案

- 数据规模与领域：主集包含 448道 题目，覆盖生物学、物理学和化学三大基础科学领域。-9

- “专家级”的硬核证据：拥有相关领域博士学位的专家准确率约为 65%，而技能娴熟的非专家即使在无限制访问网络超过30分钟后，准确率也仅有 34%。-11

- 核心子集：GPQA Diamond。这是GPQA中最具挑战性的198道题。在该子集上，博士专家的准确率可达 81.3%，而非专家准确率则低至 22.1%，区分度极高。-9-11

- 对AI的挑战：在发布之初，当时最强的GPT-4基线模型的准确率也仅为 39%，凸显了其极高的门槛。
#### 4、HLE
成为衡量AI是否达到顶尖人类专家水平的“终极学术考试”

- 数据规模与领域：包含 2,500道 题目，覆盖超过 100个 学科，从数学、自然科学到古典语言、历史等极其细分的领域。

- “防污染”的极端设计：每道题在收录前都会先让AI尝试作答，AI能答对的题目会被直接丢弃。题目由全球近千名顶尖学者贡献，并经过严格的多轮人工审核，确保其唯一正确答案和极高难度。

- 揭示“过度自信”：研究还发现，模型在答错时往往会给出很高的置信度（如80%-90%），这种“不知道自己不知道”的过度自信在医疗、法律等高风险领域是极其危险的。


### 三、聊天基准
 这部分衡量模型能否严格将输出约束到用户指定的格式/规则子空间。

#### 1、IFEval (Instruction-Following Eval)
核心机制：Judge-free（无裁判）。不依赖 LLM 打分，纯靠确定性程序（Python 脚本或正则）判定。

可验证指令（Verifiable Instructions）：定义了 25 种原子约束，如：字数限制（>400词）、包含/禁用特定词、全大写/小写、JSON 格式、段落数限制等。

评估指标拆解：

Strict（严格）vs. Loose（宽松）：Strict 直接判，Loose 会剥离 Markdown 标记（如 json）再判。

Prompt-level（提示级）vs. Instruction-level（指令级）：Prompt级要求一条 Prompt 里的所有约束全满足才算通过（Pass@1）；Instruction级按单条约束计算通过率。

底层系统关联：指令遵循是 Agent（智能体）可靠性的基石。如果模型无法稳定输出结构化的 JSON，下游的工具调用（Function Calling）和 API 解析就会直接崩溃；同时，它直接影响投机采样（Speculative Decoding）时验证阶段的接受率。


### 四、智能体与工具调用基准
将评估从“单轮问答”推向“多轮、闭环、有外部工具介入”的系统级测试。核心是评估大模型的 Agentic Scaffolding（智能体外壳） 协同能力。

#### 1、代码与工程闭环：SWE-bench

机制：从真实 GitHub 仓库提取 Issue。模型需输出 Patch（补丁代码），系统应用补丁后运行单元测试。

指标：% Resolved（成功修复合入的比例）。极度依赖模型对长篇代码的上下文理解能力。

#### 2、Web 交互：WebArena / Mind2Web

机制：在自建的、沙盒化的真实网站（如 GitLab, 购物网站）中，模型通过输出 DOM 操作指令（点击、输入）完成指定任务。

挑战：HTML 上下文极长，且需在多步交互中保持状态（State）不迷失。

#### 3、工具调用：BFCL (Berkeley Function Calling Leaderboard)

机制：给定 Python 函数库的 Schema，测试模型是否能正确提取参数并生成合法的调用代码（AST 树解析验证）。

分类：包含 Simple（单函数）、Parallel（并行多函数）、Multiple（多选一）和 Irrelevance（拒绝调用不相关函数）。

#### 五、长上下文评估
- NIAH (Needle In A Haystack，大海捞针)：在长文本的随机深度（Depth）插入一句无关但特殊的句子，要求模型找出。衡量模型在长序列中的信息检索能力。

- RULER：比 NIAH 更全面。包含多针检索（Multi-needle）、变量追踪（Variable Tracking）、聚合（Aggregation）等复杂任务，更真实地反映模型的长文推理能力。

硬件视角的挑战：长上下文评测直接压力测试系统的 KV Cache 显存管理。由于需要处理极长的 Prefill，如果不用 PagedAttention 和 FlashAttention，很容易出现 OOM（显存溢出）或严重的延迟。

### 六、 安全、对齐与可靠性评估

毒性/偏见评估：ToxiGen, BBQ (Bias Benchmark for QA)。测试模型在不同人口统计学背景下的隐性偏见。

红队测试 (Red Teaming)：如 HarmBench。输入经过伪装的越狱提示（Jailbreak Prompts），测试模型拒答率（Refusal Rate）与防御能力。

幻觉评估 (Hallucination)：TruthfulQA，HaluEval。

机制：测试模型在“对抗性”问题（如阴谋论、常见误解）上的表现。

注：在医学、法律等高敏领域，模型“一本正经地胡说八道”（幻觉）比直接拒绝回答（拒答）的危害更大。

对齐的底层实现：这些评测背后的模型通常经过了 RLHF 或 DPO，本质是给模型加了一层“安全护栏”，但也可能导致“过度对齐（Over-refusal）”（如把正常的医学咨询当成有害内容拒答）。
