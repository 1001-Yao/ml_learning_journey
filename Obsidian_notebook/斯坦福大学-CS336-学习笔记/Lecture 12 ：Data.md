#### 1. 核心定位：数据是LLM的“核心配方”

在LLM的三大要素（算力、算法、数据）中，**数据是唯一不公开的环节**。Llama 3、DeepSeek 等模型开源了权重和架构，但对数据清洗流程和配比严格保密，因为数据配方直接决定了模型的能力边界。

**训练数据的“长尾特性”**：常见样本（如日常对话、新闻）出现频率极高，而专业领域（如医学、法律）或罕见场景的数据在单一类别中出现次数很少。但由于这类少见样本的类型数量极多，它们共同决定了LLM能力的**覆盖范围**和**泛化边界**。

#### 2. 分阶段数据需求（与你的训练/推理知识衔接）

现代LLM训练已非“端到端一次性训练”，而是分三阶段，每阶段对数据的规模和质量要求完全不同：

| 阶段 | 数据来源 | 规模 | 目标 |
| :--- | :--- | :--- | :--- |
| **预训练 (Pre-training)** | Common Crawl、书籍、维基百科 | 万亿级 Token (3T–15T) | 学习语言统计规律、语法、世界知识 |
| **中期训练 (Mid-training)** | 严格筛选的高质量文本，强调 **STEM（数学、代码）** 和长上下文 | 百亿–千亿级 Token | 强化推理、数学、代码、长文本能力 |
| **后训练 (Post-training)** | 人工构造/标注：指令数据(SFT)、多轮对话、RLHF偏好数据 | 相对较小 | 指令遵循、安全交互、价值观对齐 |

**关键洞察**：中期训练是预训练与后训练的**桥梁**，它用高质量数据定向强化特定能力，而不扩展知识规模。这与第9章 Scaling Laws 中“过度训练”（用更多数据训小模型以换取推理效率）的策略直接相关。

#### 3. 数据管线的演进：从“堆量”到“淘金”

数据与训练标准的演化，是长期试错的结果：

**BERT：文档级语料的必要性**
- 使用 BooksCorpus（~8亿词）和英文维基百科（~25亿词），刻意剔除列表、表格、标题，只保留正文段落。
- **为什么？** BERT的双向Transformer需要**连续的文档级文本**来学习跨句、跨段的语义依赖。随机打乱的句子级语料（如 Billion Word Benchmark）虽然规模大，但会削弱这种能力。

**GPT-2：从网页中“淘金”**
- 不直接抓取全网，而是从 Reddit 社区精选链接：**仅收录出现在获得至少3个赞的帖子中的链接**。
- 逻辑：至少有3个用户认为该链接有价值，就排除了大量垃圾广告和低质量内容。这是“用社区信号做质量过滤”的早期实践。

**GPT-3：规模化与多样性**
- 引入 Common Crawl（全网爬取），但面临严重的噪声问题。GPT-3 的质量控制策略是后续所有数据工程的起点。

#### 4. 工业级数据管线（以 FineWeb 为参考）

搜索到的 FineWeb 管线给出了可量化的每一步淘汰率，是理解数据工程“漏斗效应”的最佳样本：

| 顺序  | 步骤                   | 解决的问题        | 产出/保留率                |
| :-- | :------------------- | :----------- | :-------------------- |
| 1   | URL 黑名单过滤            | 成人内容、已知低质量站点 | —                     |
| 2   | 正文抽取（从 WARC 而非 WET）  | 剥离导航栏、页脚、广告  | —                     |
| 3   | 语言识别（fastText）       | 只保留目标语言      | —                     |
| 4   | 启发式质量规则              | 乱码、模板、极端重复   | 36T Token             |
| 5   | MinHash 近似去重（按快照分别做） | 转载、镜像、近似副本   | 20T Token（保留 **56%**） |
| 6   | C4 过滤子集 + 自定义规则      | 更细的低质量模式     | 15T Token（保留 **75%**） |

**关键工程原则**：**便宜的过滤放前面，贵的放后面；去重放在过滤之后**，因为对垃圾做去重是白费算力。

**启发式规则的具体示例**（FineWeb 论文数据）：
- 行尾带终止标点的行占比 < 0.12 → 淘汰 10.14% 词元
- 重复行字符占比 ≥ 0.1 → 淘汰 12.47%
- 短于 30 字符的行占比 ≥ 0.67 → 淘汰 3.73%
- 三条规则合计淘汰约 **22%** 词元（小于逐条相加，因重叠）

#### 5. 关键步骤的底层机制

**正文抽取**：Common Crawl 提供 WARC（原始HTTP响应）和 WET（自带纯文本转换）。直接用 WET 省事，但正文质量不高。FineWeb 的消融实验证明：用专门工具从 WARC 重新抽取，下游成绩优于直接用 WET。Llama 3 更进一步：自建 HTML 解析器，**保留数学公式的 alt 文本**，但**去除所有 Markdown 标记**（实测保留反而有害）。

**去重（MinHash）**：Web 上存在大量转载、镜像、模板和部分修改的副本。不去重会导致模型反复学习相同内容，扭曲输出分布。MinHash 通过 Jaccard 相似度近似检测，是工业级去重的标准手段。

**数据配比（Data Mixture）**：不同来源（代码、数学、网页、书籍）的混合比例决定了模型的能力倾向。代码多则代码强，学术文献多则定义/引用风格重，对话多则礼貌/附和增加。配比调整的时机也很关键：**在预训练末期的学习率衰减阶段混入高质量/指令数据**，可以利用 Loss 的断崖式下降让模型进入正确模式，同时规避灾难性遗忘。
