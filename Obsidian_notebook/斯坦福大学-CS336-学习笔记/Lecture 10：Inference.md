### 推理优化 ->快

**“快”意味着什么（指标）？**

- **首字延迟（TTFT, Time-to-first-token）**：在任何内容生成出来之前，用户需要等待多长时间（针对交互式应用）。
    
- **延迟（秒/Token，Latency）**：针对**单个**查询，Token 出现的速度有多快（针对交互式应用）。
    
- **吞吐量（Token/秒，Throughput）**：针对**多个**查询，Token 出现的速度有多快（针对批处理）。

**什么决定了效率？**

- **训练（有监督）**：你可以看到所有 Token，可以沿着序列维度进行并行（Transformer 中的矩阵乘法）。
    
- **推理**：你必须顺序生成，无法在生成维度上并行，因此很难充分利用计算（算力）。

### 一、 核心度量：被物理定律撕裂的“两大阶段”
任何关于推理的优化，都必须基于对 **Prefill（预填充）** 和 **Decode（解码）** 的深刻理解，因为它们的物理瓶颈完全相反。

*   **Prefill 阶段（计算受限，Compute-bound）**
    *   **底层执行**：一次性处理所有的 Prompt Token。这是一个巨大的矩阵乘法（GEMM）。
    *   **硬件表现**：GPU 的 Tensor Core 被彻底打满，算力利用率（MFU）极高。此阶段的耗时直接决定了 **TTFT（首字延迟）**。
    *   **瓶颈**：受限于 GPU 的峰值 FLOPs。如果 Prompt 极长，计算量会以 $O(L^2)$ 膨胀。
*   **Decode 阶段（访存受限，Memory-bound）**
    *   **底层执行**：每次只处理 1 个 Token。原本的矩阵乘法退化成了**矩阵-向量乘法（GEMV）**。
    *   **硬件表现**：算术强度（Arithmetic Intensity）极低。为了算 1 个 Token，必须把整个模型权重（几百 GB）和庞大的 KV Cache 从 HBM 搬到 SRAM，但算力单元却只做了极少的加法。SM 极度饥饿，处于“空转”状态。
    *   **瓶颈**：死死卡在 **HBM 的访存带宽** 上。Latency（词间延迟，TPOT）取决于显存能多快把数据喂给计算单元。

### 二、 显存管理系统的重构：打破碎，压容量
这是近年来推理框架（如 vLLM, SGLang）爆发的根本原因。

*   **传统 KV Cache 的灾难**：传统的静态分配机制，不管序列实际多长，都会按 `max_seq_len` 预留显存。这导致极其严重的**内部碎片**和**外部碎片**，显存利用率（Memory Utilization）往往只有 20%~30%，直接卡死了并发吞吐量。
*   **PagedAttention（分页注意力）**：
    *   **底层原理**：借鉴操作系统的虚拟内存分页。把 KV Cache 切分成固定大小的 Block（如 16 个 Token 一页）。用逻辑映射表（Block Table）把物理上不连续的显存块拼接起来。
    *   **硬件收益**：彻底消灭显存碎片，显存利用率飙升至 90% 以上；而且实现了**内存共享（Copy-on-Write）**，对于相同的 Prompt（如系统提示词），多用户并发时可以共享同一份物理 KV 块，极大降低了显存占用。
*   **Prefix Caching（前缀缓存）**：对于长文档问答，利用 Radix Tree（基数树）算法，直接复用前文已经算好的 KV Cache，**跳过 Prefill 阶段**，极大地降低了重复计算。

### 三、 打破自回归的“串行诅咒”（系统调度层）
既然单用户 Decode 阶段算力闲置，那就把多个用户拼起来算。

*   **Continuous Batching（连续批处理/动态批处理）**：
    *   **痛点**：传统静态 Batching 要等最长的那个用户生成完才能释放所有资源，短任务被严重拖累。
    *   **底层操作**：在 GPU 每生成一个 Token（一个 Decode step）的间隙，动态地把新来的请求插进当前的 Batch 中，把算完的请求踢出去。
    *   **收益**：把多个单用户的 GEMV 强行拼成了 GEMM，重新把 Decode 变成了 **Compute-bound**，榨干了 GPU 的算力。
*   **Speculative Decoding（投机采样）**：
    *   **底层操作**：用一个小模型（Draft Model，极快）一口气猜出 5 个 Token，然后交给大模型（Target Model）在**一次前向传播中并行验证**这 5 个 Token。如果猜对 4 个，那么大模型一次就算出了 4 个 Token，打破了原有的串行生成逻辑。
    *   **硬件收益**：用小模型的计算量换取大模型的访存次数减少（因为验证是并行的，只需要搬一次大模型的权重）。数学上可以做到**绝对无损**（输出分布与大模型完全一致）。

---

### 四、 算法层的底层数学降维（模型结构优化）
为了减小 HBM 的读取压力，直接在模型结构上动刀。

*   **MQA (Multi-Query Attention) / GQA (Grouped-Query Attention)**：
    *   **物理本质**：原本多头注意力（MHA）每个头都要存一份 K 和 V，KV Cache 极大。MQA 让所有头共享 1 份 KV，GQA 让一组头共享 1 份 KV。
    *   **收益**：直接砍掉了几十倍的 KV Cache 显存占用，相当于变相**放大了 HBM 的等效带宽**。
*   **FlashAttention（推理特供版）**：
    *   **底层逻辑**：在推理时，特别是长上下文 Prefill 时，依然使用 Tiling 和 Online Softmax，避免 $N \times N$ 矩阵在 HBM 和 SRAM 之间反复搬运。
*   **量化（Quantization）**：
    *   **Weight-only 量化（如 INT4/INT8，AWQ/GPTQ）**：因为 Decode 阶段是绝对的内存墙，把权重从 FP16 压到 INT4，**模型体积直接减半/减至四分之一**。这意味着 HBM 读取带宽的消耗减半，Decode 速度几乎翻倍。
    *   **KV Cache 量化**：把存下来的 K 和 V 也压成低精度，进一步缓解长文本下的显存压力。

### 五、 终极系统架构：PD 分离（Prefill-Decode Disaggregation）
这是目前工业界（如 DeepSeek-V3, 豆包等）最火的部署方案。

*   **为什么要分离**：Prefill（吃算力）和 Decode（吃带宽）混在一个 GPU 上跑，会互相干扰。当有长 Prompt 进来时，Prefill 会霸占算力，导致正在 Decode 的用户出现卡顿（ITL 飙高）。
*   **底层拓扑**：用专门的算力节点（高算力卡）做 Prefill，算完把产生的 KV Cache 通过极快的 **NVLink 或 IB 网络** 传给专门的 Decode 节点（大显存、高带宽卡）。
*   **意义**：实现了真正的异构计算，各自跑在自己的甜点区，TTFT 和 Throughput 同时达到最优。

### 总结
硬核地看，这篇教程里的推理优化，全都是在和物理硬件拼命：
**用 PagedAttention 偷显存，用 Continuous Batching 强行堆大 Batch 破解串行，用投机采样作弊，用量化减少数据体积，最后用 PD 分离让算力和带宽各司其职。**
